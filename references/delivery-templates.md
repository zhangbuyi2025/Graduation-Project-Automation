# 交付物模板（阶段 E / 阶段 F / 交付说明）

本文件给出三个交付物的模板与填写规则：

1. `<项目名>_项目总结.md`（阶段 E 必产，校验 9 项必含内容）
2. `<项目名>_答辩PPT.pptx` 大纲（阶段 F 用）
3. 交付说明话术（流水线结束时报给用户）

约定：`<项目名>` = 中文显示名；`<snake>` = 英文 snake 名（包名、工程名）；`<db>` = 数据库名。

---

## 1. 项目总结 Markdown 模板（阶段 E）

在**项目根目录**生成 `<项目名>_项目总结.md`。必须覆盖以下 9 个区块，区块标题固定，方便阶段 F 抽取素材。

```markdown
# <项目名> 项目总结

> 生成日期：<YYYY-MM-DD>
> 项目根目录：<绝对路径>

## 1. 需求来源

- 输入形式：<PPT / 需求描述 / 三件套已存在（可重入）>
- PPT 路径：<需求 PPT 的绝对路径，或"无">
- 需求描述原文：<用户原始描述，简短引用；若为 PPT 输入则写"无">

## 2. 交付产物清单

| 产物 | 路径 | 说明 |
|---|---|---|
| 需求 PPT | <路径> | 阶段 A 生成（若输入即 PPT 则同文件） |
| ppttomd.md | <路径> | 需求中间稿 |
| 需求规格说明书.docx | <路径> | 8 章完整 SRS（Word 目录需 F9 刷新） |
| <db>.sql | <路径> | MySQL 8.0 建库脚本（表/视图/初始化/校验） |
| 交互原型.html | <路径> | 无 JS 原型，页面规格与主题来源 |
| 后端工程 | <根>/<snake>_backend | Spring Boot 3.1 + Java 17 |
| 前端工程（各角色端） | <根>/<snake>_webfront/<角色> | Vue3 + Vite，每角色一个 |
| 项目总结 | 本文件 | — |
| 答辩 PPT | <路径> | 阶段 F 产物 |

## 3. 需求规格摘要

### 角色与职责

| 角色 | 职责 | 登录入口 |
|---|---|---|
| <角色1> | <描述> | <角色端前端名> |
| <角色2> | <描述> | <角色端前端名> |

- <功能模块1>：<一句话>
- <功能模块2>：<一句话>

### 业务状态机

- 状态集合：<e.g. 待提交 → 已提交 → 审核中 → 已归档 / 已驳回>
- 流转规则：<谁在什么条件下流转到哪，驳回后可否重提>
- 硬性规则：<只读、导出、删除约束等>

## 4. 数据库设计摘要

- 数据库名：<db>
- 表清单（共 N 张）：<表1>、<表2>、…、<表N>
- 核心表 <表X> 关键字段：<字段（类型，约束）>…
- 约束要点：<唯一键、外键、状态 ENUM、软删除、双时间戳 init/update>
- 视图：<视图清单或"无">

## 5. 系统架构

- 技术栈：Spring Boot 3.1 / Java 17 / MyBatis-Plus 3.5.5 / Spring Security + JWT / Redis / POI 5.2.3 / Quartz / Mail（后端）；Vue3 + Vite + Pinia + Vue Router + Axios（前端）
- 后端包名：`com.example.<snake>`；端口：8080
- 前端工程与端口：<snake>_webfront/<角色1> → 5173、<snake>_webfront/<角色2> → 5174（从 5173 顺序分配）
- 后端分层目录：common / config / controller / dto / entity / exception / filter / mapper / service(+impl) / utils / vo
- 前端 src 目录：api.js / assets / components / layout / router / stores / utils / views
- 认证：JWT（`/api/public/`、`/api/forget/` 放行，`/api/admin/**` 需 ADMIN 角色）

## 6. 开发内容统计

### 后端（依据 SRS 实体与用例）

- 实体类：<entity><X>、...
- Controller 接口：<按模块列：模块 → 端点数量>
- Mapper / Service：<列名>
- 文件服务、导出、定时、邮件等基建：<说明或"无">

- 后端编译：`<snake>_backend` 执行 `mvnw.cmd compile` → EXIT <0 / 报错摘要>

- 种子账号：<账号1（角色）>、<账号2（角色）>、…（见 <db>.sql 初始化段）
- 统一初始密码：<明文>（SQL 中为 BCrypt 哈希，如需换密码用 PasswordEncoderUtil 生成）

## 8. 启动与部署步骤

1. 建库：MySQL 执行 `<db>.sql`（8.0+，需含建库与字符集 utf8mb4）
2. 环境：启动 MySQL、Redis；创建上传目录（application.yml 的 `file.upload-dir`，默认 `<根>\uploads\`）
3. 后端：`<snake>_backend` 下 `mvnw.cmd spring-boot:run`（或 `mvn spring-boot:run`），端口 8080
4. 前端：进入各 `<snake>_webfront/<角色>`，`npm install && npm run dev`，按端口访问
5. 维护：Word 目录 F9 刷新；SQL 密码占位符需替换为真实 BCrypt

## 9. 答辩 PPT

- 位置：<`<根>/<项目名>_答辩PPT.pptx`>
- 生成方式：阶段 F 调用 ppt-master 生成
- 素材引用：本总结 + SRS 状态机/用例 + SQL 表设计 + 原型截图 + 验证输出

## 10. 备注

- 已知限制与后续事项：<e.g. 未接邮件服务器、Quartz 任务需配置触发时间>
```

**填写规则**：

- 第 7 节必须写真实验证输出（EXIT 码、构建日志摘要），禁止编造；环境缺失导致未能验证时写明「未验证 + 原因」。
- 第 2 节产物清单的路径全部使用绝对路径。
- 若部分区块无内容（如无视图、无邮件），写「无」而非删除标题，保持 9 项结构完整。

## 2. 答辩 PPT 大纲模板（阶段 F）

调用 `ppt-master` 的 `Generate PPTX（Default）` route 时使用以下结构。页数约 12–16 页，每页一块要点；文字只需要点与数据，不得占位符式空话。

| # | 页面主题 | 必含内容 | 素材来源 |
|---|---|---|---|
| 1 | 封面 | 项目名、答辩人/团队、日期 | 阶段 E 总结 §1 |
| 2 | 项目背景与意义 | 业务痛点（2–3 条）、要解决什么问题、应用价值 | 总结 §1 + SRS 第 1 章 |
| 3 | 需求分析 | 角色清单、核心功能模块图（文字结构化）、业务状态机 | SRS 用例表 + 总结 §3 |
| 4 | 系统总体设计 | 架构图（前后端 + MySQL/Redis）、技术选型与理由、端口/包名布局 | 总结 §5 |
| 5 | 数据库设计 | 核心表 ER 结构、状态 ENUM、关键约束、初始化与种子数据 | SQL + 总结 §4 |
| 6 | 功能实现（1） | 某角色端 2–3 个核心功能：页面截图 + 实现要点（表驱动列表） | 原型/实际页面截图 |
| 7 | 功能实现（2） | 另一角色端 2–3 个核心功能：同上 | 截图 |
| 8 | 功能实现（3，可选） | 审核/流程类功能：流程时序（提交 → 审核 → 归档/驳回） | 截图 + 状态机 |
| 9 | 关键技术亮点 | JWT 无状态认证、MyBatis-Plus 分页/自动填充、文件三校验、POI 导入导出（按实际挑 2–3 个，每个 1 句话 + 关键代码片段） | 代码实现 |
| 10 | 系统演示说明 | 演示路径脚本：登录谁 → 做什么 → 看到什么结果（按角色逐步列出） | 种子账号 + 实际流程 |
| 11 | 测试与验证 | 编译/构建通过结果、接口与页面自测记录、边界用例（如非法文件、越权访问） | 总结 §7 |
| 12 | 总结与展望 | 完成情况（对照需求列表 √）、不足与后续迭代方向 | 总结 §10 |
| 13 | 致谢 | 致谢 + Q&A 提示 | — |

**要点规范**：

- 「功能实现」页必须配截图：交互原型 html 或 dev server 实际页面，浏览器打开后截图放入素材。
- 「技术亮点」只写真实用到的技术，不得堆砌模板工程里存在但本项目未使用的组件（如本项目无定时任务，就不写 Quartz）。
- 发给 ppt-master 的要点必须已有数据（角色名、表名、端口、EXIT 码），不得留待它现场发挥或编造。

## 3. 交付说明话术模板

流水线结束时按以下结构向用户汇报（路径全部替换为实际值）：

```
✅ 全流程完成：<项目名> 已从 <PPT / 需求描述> 生成完整全栈项目。

【产物清单】
1. 需求规格三件套：ppttomd.md / <项目名>_需求规格说明书.docx / <db>.sql —— <根目录>
2. 交互原型：<项目名>_交互原型.html —— <根目录>（浏览器打开可见页面规格）
3. 后端工程：<snake>_backend —— Spring Boot 3.1，包名 com.example.<snake>，端口 8080
4. 前端工程：<snake>_webfront/<角色1>（端口 5173）、<snake>_webfront/<角色2>（端口 5174）……
5. 项目总结：<项目名>_项目总结.md —— <根目录>
6. 答辩 PPT：<项目名>_答辩PPT.pptx —— <根目录>

【验证结果】
- 后端 mvnw.cmd compile：EXIT 0 ✓
- 前端各工程 npm run build：成功 ✓
- 种子账号：<清单>；统一初始密码：<明文>

【启动顺序】
1. MySQL 导入 <db>.sql
2. 启动 MySQL / Redis，创建上传目录 <路径>
3. 后端：cd <snake>_backend && mvnw.cmd spring-boot:run
4. 前端：cd <snake>_webfront/<角色> && npm run dev

【注意事项】
- Word 目录需打开后按 F9 刷新页码
- SQL 中密码为 BCrypt 占位符，如需修改用 PasswordEncoderUtil 生成新哈希
- 答辩 PPT 侧重演示与亮点，需求 PPT 侧重需求规格本身，两者勿混用
```

若退化为局部执行（用户中断或指定只做部分阶段），只汇报实际完成部分，并列出未执行步骤。
